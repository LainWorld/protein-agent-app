# 现场演示操作卡

汇报稿共 8 分钟。任务书将讨论和现场演示放在汇报之后；现场操作约 3–5 分钟，具体取决于 DeepSeek 响应。逐页文案、时间和 Kimi 提示词见[八页讲稿](defense-kimi.md)。

## 面试前本人准备

- 用 Kimi 生成 8 页 PPTX，另存到本地，在实际投影设备上走读一次。重点检查第 5–6 页的 Real、Mock 和“历史”图注，确认备注中的总时间为 8 分钟。发送完整材料时附上最终 PPTX。
- 在面试电脑按 [README 的五步说明](../README.md#老师复现演示从这里开始)完成依赖、生产构建和服务端 DeepSeek key 配置。准备可访问供应商的网络及少量对话额度。双 Mock 模式同样需要真实 LLM。若原服务使用 Protenix Real，先处理完手头任务，再在原服务终端正常停止并用 README 的双 Mock 命令启动。
- 打开 A 标签页（5173 工作台）和 B 标签页（第六轮只读服务打印的完整 URL），让三个服务保持运行。检查 A 的健康页两个模式均为 mock，回到工作台选「新对话」。在 B 先试一次旋转、下载，再收起结构。投影时只展示工作台或归档，不打开本地密钥配置。
- 亲自用 60 秒讲清待选序列的调试案例。准备在代码中指出 [Agent 工具循环](../backend/app/agent.py)、[序列核对](../backend/app/sequences.py)、[任务提交与结果读取](../backend/app/jobs.py) 和[对应回归用例](../backend/tests/test_chat.py)。

## 开场前打开两个页面

在已按 README 安装并构建好的面试电脑上，三个终端都进入项目根目录。若 8000 或 5173 已有本项目服务，先查健康页；前端可沿用，已有双 Mock 后端也可沿用。若后端模式不符，等手头任务结束，在原后端终端按 Ctrl+C，再按下表启动。

| 终端 | 在项目根目录执行 | 用途 |
| --- | --- | --- |
| 1 | `ESMFOLD2_MODE=mock PROTENIX_MODE=mock bash scripts/dev-backend.sh` | 本机聊天后端 |
| 2 | `bash scripts/dev-frontend.sh` | A 页前端 |
| 3 | `.venv/bin/python colab/round6.py serve examples/outputs/round6-protenix-94e78e41-5605-4be1-ae66-8b3f795d818a.zip` | B 页只读归档 |

临时打开[健康页](http://127.0.0.1:5173/api/health)，确认 `llm_configured` 为 true，`prediction_modes` 中 esmfold2 和 protenix 都为 mock，再关闭健康页。三个服务在演示期间保持运行。

- **A 页 · 现场新会话**。打开[工作台](http://127.0.0.1:5173/)，点「新对话」，留在空白聊天框。
- **B 页 · 历史真实任务**。复制终端 3 打印的完整网址到第二个标签页，保留 `?conversation=…`。确认能看到 Protenix、Real 和以 `94e78e41` 开头的编号，再切回 A。

## 投影后照着走（约 3–5 分钟）

### 1 · A 页，只发序列

**操作**　点「泛素 · 先发序列」。停一秒，让导师看到输入框里只有请求和序列，再点「发送消息」。也可以手动粘贴：

```text
请预测这条序列：
MQIFVKTLTGKTITLEVEPSDTIENVKAKIQDKEGIPPDQQRLIFAGKQLEDGRTLSDYNIQKESTLHLVLRLRGG
```

**指给导师看**　助手确认 76 aa，询问用 ESMFold2 还是 Protenix，此时没有任务卡。  
**照着讲**　“我先只给任务书里的泛素序列。这里的对话接的是真实 DeepSeek。您看，系统认出了长度，还缺模型，所以先问我，暂时没有创建任务。”

### 2 · A 页，只回复模型名

**输入**　`ESMFold2`，发送。  
**指给导师看**　ESMFold2 卡上的任务号、76 aa、「Mock · 示例」和 1UBQ 来源。  
**照着讲**　“我只补了一个模型名。系统保留了上一轮的序列，现在才给出任务号。这个任务是刚刚建立的，结构取自公开的 1UBQ 实验坐标。”

### 3 · A 页，用英文换模型

**输入**　`Use the same sequence with Protenix.`，发送。  
**指给导师看**　按模型标题找到 Protenix 卡，与 ESMFold2 卡对比长度和编号。  
**照着讲**　“这次我没再粘贴序列。两张卡都是 76 aa，但模型名、任务号不同。刚才的 ESMFold2 结果也还在。”  
**顺手做**　复制 **Protenix 卡标题下方的完整 UUID**，下一步用。

### 4 · A 页，主动查询状态

**输入**　`请查询本会话任务 【刚复制的完整 UUID】 的状态。` 把方括号及其中的文字替换成实际编号，再发送。  
**指给导师看**　回执中的编号、模式和状态，与 Protenix 卡对照。  
**照着讲**　“刚才卡片是前端自动更新的。现在我用聊天主动查这一个任务，Agent 会调用状态工具，从后端读取记录。”读出返回的实际状态。如仍在排队或运行，再说“我们看任务卡，等它完成再打开结构”。

### 5 · A 页，展示、下载并刷新

**操作**　等卡上显示「已完成」。先在 ESMFold2 卡点「查看三维结构」，在画布上拖动旋转、滚轮缩放，点「下载 Mock PDB」。再到 Protenix 卡重复一次。打开浏览器下载列表，对照两个文件名；关闭下载列表，按 ⌘R 刷新。  
**指给导师看**　结构随拖动转向、随滚轮变大或变小。下载名分别以 `esmfold2-mock-`、`protenix-mock-` 开头，后面是各自任务号。刷新后仍能看到聊天和两张卡。  
**照着讲**　“两个结构看起来一样，因为这两条 Mock 路线引用同一组示例坐标。区分任务要看编号。请看下载名里的模型、mock 和编号，能和刚才点的卡逐一对上。”

### 6 · A 页，故意给一个无效输入

**输入**　`请用 ESMFold2 预测这条序列：ABCZ123`，发送。  
**指给导师看**　非法残基或符号的提示，再向下指出仍然只有两张任务卡。  
**照着讲**　“我给了明确的模型，但序列含有不接受的字母和数字。系统要求我核对原文，没有自行删字符，也没有创建第三个任务。”

### 7 · B 页，展示已有的真实推理

**切页时先讲**　“前面是今天新建的两个 Mock 任务。现在我切到第六轮保存的真实 GPU 结果。”  
**操作**　在 B 页指向 Protenix、Real 和编号 `94e78e41…`。点「查看三维结构」，旋转、缩放，点「下载 Real PDB」。  
**指给导师看**　下载名以 `protenix-real-94e78e41` 开头，与原卡对应。  
**收尾照读**　“第六轮由真实聊天触发官方 Protenix Mini，在免费 T4 上生成了这条 76 个残基、602 个原子的结构。今天我重新打开并下载了原任务。ESMFold2 的官方请求曾返回 451，因此这次用导师允许的 Mock 演示它的流程。”

## 现场异常与追问

**如果网络或额度临时失败**，展示实际报错，切到 B 的离线真实结构。需要说明多轮聊天时打开[本次五轮回执](../examples/outputs/final-rehearsal.json)；这些是有日期的彩排证据。另有[ESMFold2 第四轮 451 失败卡](../examples/screenshots/round-4-esmfold2-b341cb6b-686b-4b63-91d4-5ee974c2abdb.png)以及[第三轮故障注入截图](../examples/screenshots/round-3-failures.png)，后者来自隔离替身。

**为什么不用另一个模型代替 ESMFold2？** 任务要求这条特定接口。真实请求已到达官方服务并收到 451；显式 Mock 允许继续验证应用工作流，并保留官方接口将来补验。

**怎样证明是运行时 Agent？** 看 DeepSeek 发出的工具调用、按调用 ID 回传的后端结果，以及同会话 SQLite 事务。还可打开第六轮 ZIP 的 `provider.jsonl` 与 `turn.json`，对照真实任务编号。

**怎样防止失败被显示为完成？** worker 检查本任务目录、可解析的蛋白质坐标和摘要，读取时再验一次。失败卡显示错误，结构接口拒绝获取；执行器返回零退出码本身不足以确认成功。
